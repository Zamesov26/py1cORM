# Участие в разработке

## Локальная проверка

Установите проект вместе с инструментами разработки:

```shell
pip install -e ".[dev]"
```

Перед коммитом выполните:

```shell
ruff format --check .
ruff check .
pytest -q
```

## Коммиты

Проект использует Conventional Commits:

```text
<type>(<scope>): <description>
```

`scope` необязателен. Описание пишется на английском языке, в повелительном
наклонении, со строчной буквы и без точки в конце.

| Тип | Назначение | Изменение версии |
| --- | --- | --- |
| `feat` | Новая обратно совместимая функциональность | `MINOR` |
| `fix` | Исправление ошибки | `PATCH` |
| `perf` | Улучшение производительности | `PATCH` |
| `build`, `ci`, `chore`, `docs`, `refactor`, `style`, `test` | Остальные изменения | нет |

Несовместимое изменение отмечается `!` и footer `BREAKING CHANGE:`. Пока версия
ниже `1.0.0`, такое изменение увеличивает `MINOR`.

Релиз запускается вручную workflow `Release` из ветки `main`. Версию в
`pyproject.toml`, changelog и релизные теги после начальной настройки вручную не
изменяем: это делает `python-semantic-release`.

Перед первым запуском workflow владелец репозитория один раз создаёт исходный
тег на коммите с версией `0.1.0`:

```shell
git tag -a v0.1.0 -m "Release 0.1.0"
git push origin v0.1.0
```

Без исходного тега в расчёт первой автоматической версии попадёт старая история
коммитов, созданная до введения Conventional Commits.
